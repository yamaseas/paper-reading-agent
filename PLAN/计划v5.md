请修改 `paper-reading-agent`，目标是把当前“整篇 PDF 全页转图片一次性发送给 LLM”的方案升级为 **text-first + visual-on-demand** 的论文阅读流程，并改进 Q1–Q7 与 Mermaid 输出。

### 1. 输入改成 text-first + visual-on-demand

修改 `config.yaml`：

```yaml
input:
  mode: hybrid_text_visual
  extract_text: true
```

保留现有 PDF 页面渲染能力，但**主阅读请求不再发送全部 page images**。

复用 `src/preprocess.py` 已存在的：

```python
extract_text_with_pages()
```

生成带：

```text
--- PDF_PAGE=N ---
```

标记的全文文本。

修改 `src/reader.py`：

* `Reader.read()` 增加全文 text 输入。
* `_build_messages()` 主阅读阶段发送：

  * paper metadata
  * page-marked full text
  * report schema
* 不再默认上传所有 page images。
* 当模型认为 table / figure / equation / layout 无法从文本可靠判断时，通过现有 `visual_requests` 请求对应 PDF page/crop。
* visual refinement 继续使用现有 300 DPI crop/page rendering。
* 保留现有 request budget、retry、schema repair、unresolved_items 机制。

暂时不要更换 PyMuPDF parser；先完成最小可用版本并方便后续 A/B test。

### 2. Evidence schema 支持文本证据和视觉证据

修改 `schemas/report.schema.json`。

当前 evidence 强制：

```json
"image_id"
```

改为通用 evidence source，例如：

```json
{
  "id": "e1",
  "source_type": "text",
  "pdf_page": 5,
  "source_id": "page-005-text",
  "section": "3.2 Task Formulation",
  "figure_or_table": "",
  "locator": "paragraph ...",
  "quote": "..."
}
```

视觉证据：

```json
{
  "id": "e2",
  "source_type": "image",
  "pdf_page": 7,
  "source_id": "crop-01",
  "section": "4 Evaluation",
  "figure_or_table": "Figure 5",
  "locator": "...",
  "quote": ""
}
```

其中：

```text
source_type = text | image
```

不要再要求每条 evidence 都有 `image_id`。

同步修改：

* `src/validate.py`
* `src/render_report.py`
* evidence link/rendering
* tests

### 3. 最终报告固定为 Q1–Q7

修改 schema、`prompts/reader.md` 和 `render_report.py`，最终 Markdown 使用以下固定标题：

```text
Q1: 这篇论文试图解决什么问题？
Q2: 有哪些相关研究？
Q3: 论文如何解决这个问题？
Q4: 论文做了哪些实验？
Q5: 有什么可以进一步探索的点？
Q6: 总结一下论文的主要内容
Q7: 想要进一步了解论文
```

具体要求：

#### Q1

包含：

* background
* existing limitation / gap
* research problem
* motivation
* contributions

#### Q2

按研究类别组织 related work，说明：

* work
* problem
* method
* 与本文区别

#### Q3

重点回答：

* input
* overall idea
* components
* workflow
* intermediate artifacts
* tools/models
* feedback loops
* decisions/branches
* output

#### Q4

每个实验独立组织：

* experiment purpose
* dataset/sample size
* baseline
* model/system
* metrics
* settings
* main result
* conclusion

没有显式 RQ 时不要编造 RQ 编号。

#### Q5

拆成：

```text
作者明确提出的 Future Work
基于本文结果可以继续探索的问题
值得进一步研究的具体方向
```

必须区分作者观点和 Reader/LLM analysis。

#### Q6

生成可独立阅读的完整论文总结。

#### Q7

定位为：

> 读完 Q1–Q6 后，如果研究者还想深入理解、复现或研究本文，下一步应该关注什么？

优先包含：

```text
最值得精读的章节 / Figure / Table
需要补充理解的关键概念
最值得继续追问的问题
复现论文需要关注什么
值得继续阅读的相关方向
```

不要重复 Q6。

### 4. Mermaid 不再生成简单线性流水线

当前 `A -> B -> C -> D` 式方法图信息量太低。

修改方法/diagram 数据结构，至少支持：

```json
"diagrams": [
  {
    "id": "...",
    "title": "...",
    "type": "...",
    "nodes": [],
    "edges": []
  }
]
```

一篇论文允许生成 **1–4 张 Mermaid 图**，而不是强制只有一张。

Diagram generator 必须在论文有证据支持时表达：

```text
输入 / 输出 artifact
核心 processing components
intermediate artifacts
branch / decision
iteration / feedback loop
parallel paths
execution / verification oracle
external tools / models
environment
training / inference / evaluation 等不同阶段
```

复杂流程使用 Mermaid `subgraph` 分阶段。

质量标准：

> 研究者只看 Mermaid 图，应该能够大致复述 Q3 的方法执行流程。

禁止为了简洁把有意义的 feedback loop、branch、oracle、intermediate artifact 全部压缩掉。

---

### 5. Mermaid 从主阅读任务中解耦

不要要求第一次 Reader 调用直接写 Mermaid。

流程改为：

```text
PDF
→ local text extraction
→ evidence extraction / PaperMap
→ visual_requests
→ selective visual refinement
→ grounded report data
→ Q1–Q7 rendering
→ Mermaid generation
→ final.md
```

Mermaid generator 只读取已经确认的：

```text
method nodes
steps
artifacts
conditions
loops
evidence
```

不要重新阅读整篇 PDF。

---

### 6. refinement 尽量避免整份 report 重写

当前 refinement 看几张 crop 后要求重新生成完整 report JSON，容易产生 unrelated drift。

如果改动成本可控，将 refinement 输出改成 patch，例如：

```json
{
  "evidence_updates": [],
  "claim_updates": [],
  "method_updates": [],
  "experiment_updates": [],
  "resolved_visual_requests": []
}
```

由 Python deterministic 地 merge 到 candidate report。

如果本轮改动过大，可以先保留现有完整 report refinement，但把该项记录为 TODO。

### 7. 测试与兼容性

新增/更新测试，至少覆盖：

1. 全文文本进入 main reader call。
2. main call 不再上传全部页面图片。
3. visual request 能正确渲染并补看指定 page/crop。
4. text evidence 和 image evidence 都能通过 schema validation。
5. final.md 正确输出 Q1–Q7。
6. Q7 不为空且不与 Q6 完全重复。
7. Mermaid 支持多个 diagram 和 subgraph。
8. 原有 retry / format repair / unresolved_items 逻辑不回归。

完成后运行：

```bash
uv run pytest -q
```

最后给出：

```text
1. 修改了哪些文件
2. 新的数据流
3. schema 变化
4. 是否存在 backward compatibility 问题
5. pytest 结果
6. 尚未完成的 TODO
```

不要在本次修改中引入 multi-agent、向量数据库、RAG、Docling 或 GROBID；先把 V2 主路径做正确、做稳定。
